# Repository Phase 42 — Explicit Slicer Interaction Authoring Design

Status: **PROPOSED — APPROVAL REQUIRED**

## Starting state and milestone

Repository Phase 41 is implemented at `HEAD` as backend-only additive
`local-pbir-generation-request/v6` report composition. It supports typed page
templates, sections, slots, navigation, slicer definitions, and a narrow
slicer-interaction field. The current field validates target IDs but does not
project explicit slicer-to-visual rules; the serializer currently emits only
the existing global interaction matrix.

The authoritative roadmap names Repository Phase 42 as the next milestone and
recommends the smallest remaining typed authoring capability before public RPC
or VS Code exposure. This proposal selects **explicit slicer interactions**
over broader report-level reusable composition because Phase 41 already
provides report composition primitives and the interaction field is the
narrowest incomplete contract seam.

## Goal

Add a backend-only additive `local-pbir-generation-request/v7` contract that
projects explicit, deterministic slicer-to-visual interaction rules through
the existing PBIR intermediate representation, pinned-schema serializer,
materialization path, and analyzer round-trip.

V1–v6 requests, records, overloads, generated bytes, hashes, and behavior
remain unchanged. V7 is not a public provider, RPC, VS Code, Desktop,
Windows, hosted, semantic-model, DAX, deployment, publishing, or mutation
surface.

## Contract

V7 adds a typed interaction collection associated with a page composition:

- source visual ID, which must identify a slicer on that page;
- ordered target visual IDs, or an explicit page-scope target;
- typed interaction mode using the existing schema-backed `CrossFilter`,
  `CrossHighlight`, or `Disabled` semantics;
- explicit enabled state and stable interaction identity for diagnostics.

The existing V6 slicer field remains accepted for compatibility. V7
normalizes it into the new internal representation only when the resulting
meaning is unambiguous; V6 output and behavior are not changed.

The first V7 slice supports same-page targets only. Cross-page interactions,
synchronized/shared slicers, bookmarks, drillthrough, custom event graphs,
and arbitrary PBIR objects remain deferred.

## Validation and projection

Validation fails closed for unknown sources or targets, non-slicer sources,
self-targets, duplicate targets, duplicate interaction identities,
cross-page targets, unsupported modes, conflicting rules, and interactions
that cannot be represented by the pinned schema.

Normalization sorts only where the contract declares order non-semantic;
request order remains meaningful for fields where existing provider behavior
preserves order. The normalized interaction model is carried into the shared
IR as explicit source/target/type records. The serializer emits the existing
schema-backed `visualInteractions` entries in deterministic order. Existing
global interaction behavior remains the fallback for V1–v6 paths.

## Data flow

```text
V7 request
  -> V7 contract and scope validation
  -> deterministic interaction normalization
  -> existing page/visual authoring projection
  -> explicit visual-interaction IR records
  -> Phase 29 serializer and pinned-schema validation
  -> Phase 31 materialization
  -> analyzer round-trip and hashes
```

## Success contract

- V7 emits schema-valid explicit slicer interaction entries.
- Identical V7 requests produce byte-identical artifacts and equal artifact,
  manifest, file-set, lineage, and interaction hashes.
- Invalid interaction scope and cardinality fail before serialization or file
  mutation.
- V1–v6 focused compatibility tests remain green with unchanged outputs.
- Representative V7 output completes materialization and analyzer round-trip.
- The Phase 29 serializer remains the only PBIR mapping boundary, and
  `PbirScoringService.cs` remains unchanged.

## Prerequisites and approval gates

- Approve this Phase 42 design and its implementation plan.
- Confirm the pinned PBIR schema evidence for explicit same-page
  `visualInteractions` entries and the supported interaction type strings.
- Preserve the clean unrelated-work boundary and establish a focused
  baseline before implementation.
- Do not add public RPC/VS Code exposure or activate the Phase 35 provider
  runtime as part of this milestone.

## Deferred boundaries

Report-level reusable composition, synchronized slicers, cross-page filter
propagation, bookmarks, drillthrough, dedicated tooltip emission, semantic
model/DAX generation, external execution, deployment, publishing, and public
surfaces remain later decisions.
