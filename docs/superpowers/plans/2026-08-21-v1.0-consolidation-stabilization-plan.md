> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Restore a reproducible release path and consolidate the existing PBIR review workflow behind characterized behavior and enforceable engineering controls, without adding roadmap capabilities.

**Architecture:** Establish release and evidence contracts first, then characterize current scoring, mutation, and protocol behavior. Use the dependency graph to introduce domain boundaries and generated contracts incrementally. ## Proposed developer-control matrix

| Location | Checks | Rationale |
|---|---|---|
| Pre-commit | changed-file formatting, ESLint, contract freshness, version/reference checks, changed-doc links | fast feedback and low bypass pressure |
| Pre-push | affected Jest, TypeScript compile, targeted .NET tests, architecture tests, contract compatibility | catches local integration failures without full release cost |
| Pull request CI | full tests, lint, compile/build, characterization, architecture, contracts, packaging, package contents, security policy, docs/version/target validation | authoritative merge gate |
| Release/tag CI | clean rebuild, supported targets, packaged acceptance, same-input determinism, safe mutation/export, checksums, provenance, SBOM, artifact manifest, publication gates | proves what users receive |
| GitHub rules | PR required, no direct main pushes, required checks, resolved conversations, protected tags, release approval | server-side enforcement |
