# Report Design Studio – Design Specification

## Vision

Transform PBIR Design Analyzer from an Analytics Experience Review Platform into an Analytics Experience Design Platform.

The platform should not merely review reports after they are built.

It should help create better reports before they reach production.

The design philosophy is:

Microsoft skills generate.

PBIR Design Analyzer evaluates.

The combination creates a closed-loop design system.

# Problem Statement

Current workflow:

Business Need
↓
Developer Creates Report
↓
Review
↓
Fixes
↓
Deploy

Problems:

- Design quality depends heavily on individual experience.
- Storytelling is often discovered too late.
- Governance is reactive.
- Report generation tools lack independent validation.

Microsoft's new AI-powered reporting skills improve creation speed but do not solve quality assurance.

---

# Strategic Positioning

PBIR Design Analyzer should become:

Analytics Experience Design Platform

Not:

AI Report Generator

Not:

Power BI Copilot Replacement

Not:

Fabric App Builder

The differentiator is:

Design Intelligence

not

Generation.

---

# Guiding Principle

Generation and Review remain separate systems.

Report Design Studio may generate recommendations or draft assets.

PBIR Design Analyzer remains the authority for:

- Story Assessment
- Issues
- Fix Plan
- Evidence
- Governance
- Readiness

No generated asset bypasses review.

# Core Concept

## Design Intent

The user provides:

- business objective
- audience
- decisions to support
- KPI priorities
- semantic model

Example:

Create an executive sales performance dashboard for regional sales managers focused on revenue, margin, and forecast risk.

---

## Design Brief

The system creates:

- intended story
- intended audience
- intended actions
- intended navigation flow
- intended KPI hierarchy

The Design Brief becomes the evaluation contract.

---

# Design Studio Modes

## Mode 1

Report Concept Studio

Outputs:

- page recommendations
- KPI hierarchy
- navigation flow
- storytelling structure

No report generation.

---

## Mode 2

Report Draft Studio

Outputs:

- PBIR draft assets
- page structures
- visual suggestions
- navigation structures

Runs in isolated workspace.

Never writes to production assets.

---

## Mode 3

Refinement Studio

Uses:

- Story Assessment
- Issues
- Fix Plan

to generate improved alternatives.

Examples:

- alternate layouts
- alternate KPI hierarchies
- alternate navigation paths

# Microsoft Skills Integration

Use Microsoft skills as:

- authoring inspiration
- generation engine
- PBIR authoring patterns
- Fabric deployment patterns
- screenshot iteration patterns

Do not:

- import skills directly
- depend on a specific provider
- couple architecture to Microsoft implementation details

Treat skills as optional providers.

---

# Trust Boundary

Never allow:

- silent report creation
- silent report modification
- direct deployment
- hidden mutations

Always require:

- review
- evidence
- validation

before deployment.
